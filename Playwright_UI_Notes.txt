#Install Playwright (skelton for framework)
1) npm init  > initialize a new Node.js project with package.json (npm init)
2) npm init playwright 
Initializes a Playwright project.
Creates a basic project structure with recommended defaults.
Installs Playwright and its dependencies.
Generates a playwright.config file for configuration.
Adds example tests so you can run Playwright immediately.
Note: if node.js is not installed, it will throw error npm is not recognised command
> Note: npm install, will install all dependencies in package.json file


Notes:
> All The Test are named as filename.spec.js (spec will make sure )
> test keyword is used to define a test case. which accepts test description & function as arguments
example:test("first platwright",function(){});
Note: Test description Must me always unique, playwright will throw error in any other cases
> JS is asynchronous  (means code wont execute line by line ), so we use async (for function), await (for code line)
 keywords explicitly (by declaring await we are telling JS to wait until the line of code execution is completed) & the function should be declared async
Note : Without Declaring method as async, await declared at line is no use 

> MAIN IMPORT: for writing assertions & tests

const { test, expect } = require('@playwright/test');

Fixtures:
1) Browser
test("browser fixture", async ({ browser }) => {
    // browser is given to you
});
Notice: you don’t new Browser() here.
>Instead, Playwright’s test runner automatically gives you a browser object 
>This is called a fixture → a ready‑made tool that Playwright sets up and cleans up for you (declared inside flowers {} as param to function)..
> This is unlike Selenium , where we will manually set up webdriver (open,manage,close) on our own
>Browser Fixture is universal, accesible to each test annotation
>whenever a test annotation is declared, Fixtures are available immediately to be used

2)page
test("page fixture",async ({page}) =>{

})
> playwright also provides page fixture, which we can use directly to launch pages without need to
declare browser/context (will assume default browser/context values)

playwright config file (basics)
1)testDir
 testDir: './tests' > use to define tests needs to be run
2)timeout 
default timeout is 30 seconds, to over ride the default timeout (timeout : 40*1000) , this timeout is for each timeout
3)expect
expect assertion timeout , this timeout if for explicitly playwright assertions, not for code

    timeout : 40*1000,
},
4)browser
defining browser (tests to be launched in)

     browserName : 'chromium'
},
5)report
report format 
reporter:'html',

6) we can export this default setup
module.exports = config

7) headless mode
true/false (boolean)
use: {
     browserName : 'chromium',
     headless : true,
   }

8) screenshot, trace, video
screenshot:'on' (to be inserted inside USE Object)
trace:'true' or 'retain-on-failure'

note : 
> screenshot can be set to 'on', 'off', 'only-on-failure'
> video can be set to 'on', 'off', 'on-first-retry', 'retain-on-failure'

8)Projects
> to run tests on multiple browsers , we need to use Projects

  {
    name: 'chrome',

      screenshot: 'on', // capture screenshots for debugging
      trace: 'on', // keep trace for failed tests

      ignoreHTTPSErrors: true, // useful for local testing
    },
  },
];

1)getByLabel
> Applicable to elements with Label Tag & Visible Text of The Tag
Ex:
<label class="form-check-label" for="exampleCheck1">Check me out if you Love IceCreams!</label>
click operation:
await page.getByLabel('Check me out if you Love IceCreams!').click();

Note: GetByLabel is suitable for Radio/Check/Dropdowns , not recommended for text-boxes due to inconsistencies

2)getByPlaceholder
> Can Be Used, When Element has placeholder attribute 

Ex:
<input class="form-control" id="exampleInputPassword1" placeholder="Password" type="password">
 await page.getByPlaceholder('Password').fill('123');

3)getByRole
> Used to locate based on their role, accepts parameter (locatortype, locatorvisiblename)
Page.getByRole(role: "alert" | "alertdialog" | "application" | "article" | "banner" | "blockquote" | "button" | "caption" | "cell" | "checkbox" | "code" | "columnheader" | "combobox" | "complementary" | "contentinfo" | "definition" | "deletion" | "dialog" | "directory" | "document" | "emphasis" | "feed" | "figure" | "form" | "generic" | "grid" | "gridcell" | "group" | "heading" | "img" | "insertion" | "link" | "list" | "listbox" | "listitem" | "log" | "main" | "marquee" | "math" | "meter" | "menu" | "menubar" | "menuitem" | "menuitemcheckbox" | "menuitemradio" | ... 36 more ... | "treeitem", options?: {
    ...;
} | undefined): Locator
Allows locating elements by their ARIA role, ARIA attributes and accessible name.

Ex:
<input class="btn btn-success" type="submit" value="Submit">
await page.getByRole('button', { name: 'Submit' }).click();

4)getByText
> It will surf through page & locate element with text

Ex:
<div class="alert alert-success alert-dismissible">
     <a aria-label="close" class="close" data-dismiss="alert" href="#">×</a>
<strong>Success!</strong> The Form has been submitted successfully!.
</div>

await page.getByText('Success! The Form has been submitted successfully!.').isVisible()

5)Filter
>Applicable on Locator

(method) Locator.filter(options?: {
 has?: Locator | undefined;
 hasNot?: Locator;
 hasNotText?: string | RegExp;
 hasText?: string | RegExp;
 visible?: boolean;
} | undefined): Locator

This method narrows existing locator according to the options, for example filters by text. It can be chained to filter multiple times.

Usage

const rowLocator = page.locator('tr');
// ...
await rowLocator
 .filter({ hasText: 'text in column 1' })
 .filter({ has: page.getByRole('button', { name: 'column 2 button' }) })
 .screenshot();

@param options

Ex:
>Filter Product with 'Nokia Edge' text & then clicking on it Add Button
 await page.locator('app-card')
              .filter({ hasText: 'Nokia Edge'})
              .getByRole('button', { name: 'Add' }).click();

--------------------------------parallel---------------------

 Once all tests are triggered under tests, 
 >All test Files will be triggered parallel
 > tests will be triggered sequentially

By Default plwyright gives 5 workers (each worker represent one test file, which can be configured)
> each worker is separately run, parallely
Ex: Running 15 tests using 5 workers 

No Of workers Can be set,in playwright.config.js file, universal

const config = {
    workers = 5
}

> suppose we want to run all tests in a test file in parallel, we can use 
test.describe.configure({mode:'parallel'}), this should be put above all tests in the test file, 
to run all files in that file in parallel

test.describe.configure({mode:'serial'}), this mode can be used when there is a data dependency , for 2nd test based on 1st test
> in cases of mode:serial, since tests will execute serially, if one of test fails then all its succeding tests will be skipped
